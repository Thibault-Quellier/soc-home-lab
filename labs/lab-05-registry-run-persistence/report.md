## 1. Executive Summary

This lab documents the detection and analysis of a persistence technique based on the modification of Windows Registry "Run keys".
The objective of this scenario is to demonstrate how a malicious actor can achieve persistence on a Windows endpoint by adding a startup entry in the registry, and how this activity can be detected using native Windows logging, Sysmon, and Wazuh SIEM.

The lab focuses on:

- Registry-based persistence using "HKCU\Software\Microsoft\Windows\CurrentVersion\Run"
- Visibility provided by PowerShell Script Block Logging
- Detection and correlation at the SIEM level using Wazuh
- Mapping of the activity to MITRE ATT&CK techniques

All actions were performed in a controlled SOC home lab environment for defensive and detection purposes only.

## 3. Attack Scenario Description

The attack scenario simulates a common persistence technique where an attacker adds a malicious command to a Windows Registry Run key to ensure execution at user logon.

 3.1 Persistence Technique

The following registry path was modified:

HKCU\Software\Microsoft\Windows\CurrentVersion\Run

A new value was created that launches PowerShell with hidden execution settings at each user logon.

 3.2 Execution Method

The persistence was established using PowerShell with the following characteristics:

- Use of "New-ItemPropert"
- Execution via PowerShell
- Hidden window execution
- No profile loading

This method is commonly observed in real-world malware and post-exploitation frameworks.

 3.3 Expected Detection Points

The activity is expected to generate:

- PowerShell Script Block Logging events (Event ID 4104)
- Possible Sysmon Registry or Process events (depending on configuration)
- Wazuh SIEM alerts based on suspicious persistence behavior

## 5. Log Analysis

This section analyzes the logs generated by the registry persistence activity and explains how the detection was achieved.

 5.1 PowerShell Script Block Logging (Event ID 4104)

PowerShell Script Block Logging captured the full command used to create the registry Run key.

Key observations:

- The use of "New-ItemProperty"
- Modification of the "Run" registry path
- PowerShell execution with hidden window options
- Clear visibility of the persistence command in plain text

This confirms that Script Block Logging provides high-fidelity visibility into PowerShell-based attacks.

 5.2 Endpoint Context

The event clearly identifies:

- The affected host (WIN-CLIENT)
- The executing user context
- The exact registry path modified
- The persistence mechanism used


## 6. SIEM Detection & MITRE ATT&CK Mapping

Wazuh successfully collected and correlated the PowerShell Script Block Logging event from WIN-CLIENT.

### 6.1 Wazuh Alert

Wazuh raised a security alert indicating:

- Suspicious modification of a Windows startup registry key
- Execution via PowerShell
- Potential persistence behavior

The alert provides structured fields extracted from the original Windows event, allowing efficient SOC-level triage.

 6.2 MITRE ATT&CK Mapping

The detected activity was mapped to the following MITRE ATT&CK techniques:

| Technique ID | Name | Description |
|--------------|------|-------------|
| T1547.001 | Registry Run Keys / Startup Folder | Adversaries may achieve persistence by modifying registry run keys |
| T1059.001 | PowerShell | Execution of commands using PowerShell |

This mapping accurately reflects the attacker behavior demonstrated in this lab.


## 7. Conclusion

This lab successfully demonstrated how registry-based persistence techniques can be detected using native Windows logging and SIEM correlation.

Key takeaways:

- PowerShell Script Block Logging provides detailed visibility into registry modifications
- Registry Run key persistence is a common and effective attacker technique
- Wazuh SIEM can correlate PowerShell activity and raise meaningful alerts
- MITRE ATT&CK mapping enhances analyst understanding and triage efficiency

This scenario reinforces the importance of endpoint telemetry and proper log collection for detecting persistence mechanisms in enterprise environments.
